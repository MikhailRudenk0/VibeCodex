# Отправка файлов и возврат в проект

> Дата создания: 2026-11-22

## Поведение

По просьбе пользователя агент прикрепляет готовый файл инструментом `send_file`.
Получатель определяется активным Telegram-запросом: чат, тема и проект не
передаются агентом в аргументах инструмента. Допустимы только `path` и `caption`.
Успех возвращается после подтверждения `sendDocument`; неопределённый результат
загрузки не повторяется автоматически.

Проект должен находиться внутри `allowedProjectRoot`. Настройка
`codex.fileDeliveryMcp: true` подключает локальный MCP-адаптер при старте или
возобновлении беседы. Адаптер не получает Telegram-токен. Приватный Unix-сокет
связывает его с ботом, который проверяет активный запрос, соединение и файл.
Сохраняются ограничения на выход за корень, симлинки, жёсткие ссылки,
тип и размер файла; загрузка использует проверенный открытый дескриптор.

## Исправление от 22 ноября 2026

Ошибка воспроизводилась при последовательности **проект A → проект B → проект A**.
Первая отправка и переход в B работали. Возврат в сохранённую беседу A приводил
к `This file tool is no longer attached to the active conversation` ещё до
вызова Telegram.

Причина: уже загруженная беседа сохраняет прежний MCP-процесс с его старым
окружением. Новая конфигурация при `thread/resume` не заменяет этот процесс,
хотя бот уже выпустил новый ключ соединения. Проверка старого ключа правильно
отклоняла отправку.

`CodexBridge.prepareFileConnection()` перезапускает app-server перед началом
следующего хода при смене беседы, каталога, чата или темы. Это выгружает старые
MCP-процессы; существующая история возобновляется с диска и получает новое
соединение. Повторный запрос в том же контексте переиспользует соединение.
Старые ключи не разрешаются и проверки получателя не ослабляются.

Перезапуск выполняется **до** создания нового `activeDelivery`: обработчик
закрытия app-server отменяет текущий контроллер, поэтому нельзя закрывать
процесс уже после привязки следующего запроса.

## Проверки

```bash
node_modules/.bin/tsc --noEmit
node_modules/.bin/tsx test/file-delivery-switch.ts
node_modules/.bin/tsx test/file-delivery.ts
node_modules/.bin/tsx test/file-gateway.ts
node_modules/.bin/tsx test/dynamic-tool-protocol.ts
node_modules/.bin/tsx test/config.ts
```

`file-delivery-switch.ts` проходит через публичный `sendMessage`, настоящий
локальный шлюз и подставные app-server/Telegram. Проверяются восемь загрузок,
возврат к обеим беседам без потери истории, новый диалог в прежнем каталоге,
смена чата/темы, отсутствие лишнего переподключения в том же контексте и
очистка разрешения после завершения хода.

Остальные проверки покрывают старые ключи, неверный чат/тему, отмену,
повторяющиеся ID вызовов, ошибки загрузки, доступ к файлам и двусторонний RPC.

Для явной проверки интеграции с установленным Codex:

```bash
node_modules/.bin/tsx test/file-mcp-switch-live.ts
```

Этот тест создаёт изолированные каталоги, один короткий ход модели для
сохранения первой беседы и три вызова файлового инструмента. Telegram
заменён тестовой реализацией; пользовательские чаты не получают сообщений.
Воспроизведение до исправления: две успешные загрузки, возврат отклонён.
После исправления: три успешные загрузки, ID первой беседы сохранён.
Проба без первого хода модели не подходит: беседа ещё не сохранена,
возврат создаёт новую и маскирует исходную ошибку.

Итоговая проверка **2026-11-22T19:10:55+01:00**: TypeScript и все пять перечисленных
офлайн-скриптов прошли в рабочем каталоге и в изолированной копии ровно
подготовленного Git-дерева. Живое воспроизведение также повторно прошло в
изолированной копии: 3/3 загрузки в тестовый адаптер, сохранение ID беседы.
Восемь переходов публичного `sendMessage` прошли 8/8 без реального Telegram.
Строка об отказе беседе вне корня в `file-delivery.ts` ожидаема: это проверка
изоляции, после которой тест подтверждает создание безопасной новой беседы.

## Применение

Изменения исходников требуют перезапуска Telegram-процесса. Для текущего
инстанса `projects` применяется отложенный перезапуск после завершения ответа;
он не стирает выбранный проект и историю. До него текущий процесс продолжает
использовать прежний код. Отправка реальных рекламных PNG остаётся отдельной
проверкой после переподключения; тестовый `sendDocument` не доказывает доставку
файла пользователю.

Локальная реализация автоматической отправки и её проверки существовали до
этой задачи, но не были полностью сохранены в Git. Для воспроизводимости
исправления в коммит включены необходимые модули и интеграция отправки.
Независимые изменения восстановления текстовых ответов и голосового ввода
не относятся к этой правке.
