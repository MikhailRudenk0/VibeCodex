# Обновление списка моделей Codex

24.11.2026: по запросу пользователя в Telegram-меню должны появиться
`gpt-6.2-sol` и `gpt-6.2-astra`, уже присутствующие в свежем каталоге Codex.
Причина устаревания: bridge возвращал первый непустой список до перезапуска бота.

Теперь каждый `getSupportedModels()` вызывает read-only `model/list` с limit=100.
Меню сохраняет серверные ID, подписи и порядок, скрытые модели исключаются;
доступные effort обновляются вместе со списком. При успешном пустом ответе
старые модели удаляются. При ошибке RPC возвращается последний успешный список.
Текущие модель, effort, сессия и рабочий каталог не переключаются.

Это не закреплённый вручную список доступов. RPC может использовать каталог
клиента/кэш Codex; наличие модели в нём не заменяет подтверждение права вызова
успешным inference. Отдельный app-server установленной версии CLI вернул обе
модели 6.2; модельные вызовы ради проверки меню не требуются.

Проверки: `node_modules/.bin/tsx test/model-catalog.ts`, TypeScript;
живой `getSupportedModels()` через отдельный app-server, без `turn/start` и
без Telegram-сообщений. Автотест проверяет появление 6.2 после старого списка,
скрытые/удалённые модели, effort, временный сбой, пустой каталог и сохранение выбора.
Все проверки прошли. Живой каталог: 10 моделей, 3 запроса `model/list`, обе 6.2
содержат effort `low`. Новых inference-вызовов — 0; скорость обработки и
математическое качество аннотаций этой проверкой не измерялись.

Изменение исходников требует перезапуска инстанса. Для текущего management
используется отложенный перезапуск по штатному `bin/bots.sh defer management`
после завершения ответа: текущий диалог и новые активные задачи прерывать нельзя.
Проверка результата перезапуска — management/restart.log.
